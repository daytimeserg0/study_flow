# Демонстрация StudyFlow

[README](../README.md) · [API](api.md) · [Архитектура](architecture.md)

## Подготовка

После запуска приложения из README:

```powershell
docker compose exec web python manage.py seed_demo
```

Для локальной среды без Docker:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
```

Нужен `DJANGO_DEBUG=True`. Новые аккаунты получают пароль `StudyFlow-demo-2026!`;
параметр `--password` задаёт другой пароль при их создании. Повторный запуск
сохраняет существующие пароли, профили, ответы, оценки и сроки. Демообъекты,
которые отсутствуют, создаются снова. Уже существующий пользователь с занятым
демоименем, но без метки демонстрации, вызывает ошибку; выполнение откатывается
целиком. Отключённые аккаунты и изменённые роли также требуют явного исправления.

Курсы определяются по преподавателю и названию, задания - по курсу и названию.
Названия из таблиц ниже зарезервированы для демосценария. При переименовании
старый объект сохраняется, а команда создаёт новый пример с исходным названием.
Несколько совпадающих объектов вызывают ошибку с полным откатом.
Если изменённый максимум не позволяет восстановить демооценку или пример
опубликованного задания стал черновиком, команда также останавливается без изменений.

Открытые сроки назначаются на 14 дней вперёд при первом заполнении. Позже сроки
демозаданий можно обновить:

```powershell
docker compose exec web python manage.py seed_demo --refresh-deadlines
```

Флаг обновляет только сроки демонстрационных заданий: открытые снова оказываются
в будущем, пример просроченного задания - в прошлом. `--json` выводит идентификаторы
созданных или найденных объектов без пароля. Фиксированные значения ID не используются.

## Что появится в базе

| Аккаунт | Доступ |
| --- | --- |
| `demo_teacher` | Владелец `[Demo] Основы Python` |
| `demo_other_teacher` | Владелец `[Demo] Базы данных` |
| `demo_student` | Зачислен только на Python |
| `demo_peer` | Зачислен на оба курса |

Ни у одного демоаккаунта нет прав Django Admin. Администратор создаётся отдельно
командой `createsuperuser`.

В курсе Python:

| Задание | Состояние | Максимум | Работы |
| --- | --- | --- | --- |
| Подсчёт слов | Опубликовано, срок открыт | 100 | `demo_student`: 80 баллов; `demo_peer`: ожидает проверки |
| Коллекции | Опубликовано, срок открыт | 50 | Решений пока нет |
| Работа с файлами | Опубликовано, срок истёк | 25 | Решений нет |
| Итераторы | Черновик | 100 | Скрыто от студентов |

В курсе баз данных опубликовано `SQL JOIN`; работа `demo_peer` оценена в 70 из 100.
Она не влияет на прогресс курса Python.

Сразу после первого заполнения у `demo_student` в Python: 3 опубликованных задания,
1 сданное, 1 проверенное, 1 просроченное без решения, 80 из 175 баллов и завершённость
33,33%. Данные меняются по мере прохождения сценария.

## Работа через интерфейс

1. Откройте [StudyFlow](http://127.0.0.1:8000/) и нажмите **Войти студентом**.
   Можно также ввести `demo_student` и пароль из раздела подготовки вручную.
2. Откройте `[Demo] Основы Python`, затем **Коллекции**. Нажмите
   **Отправить решение**, введите текст или ссылку и отправьте форму.
   До проверки и окончания срока работу можно изменить.
3. Нажмите **Выйти**, затем **Войти преподавателем**. Откройте тот же курс
   и задание: в разделе **Работы студентов** появится отправленное решение.
4. Нажмите **Проверить работу**, поставьте оценку от 0 до 50 и оставьте комментарий.
5. Войдите студентом ещё раз: оценка и комментарий видны в задании, редактирование
   проверенного решения закрыто. Во вкладке **Прогресс** курса обновятся показатели.

У преподавателя также есть **Создать курс**, **Добавить студента** во вкладке
**Участники**, создание и публикация заданий. Новое задание сначала сохраняется
черновиком и не видно студентам. Удалить можно только черновик.
Поиск, фильтры и страницы списков работают через API; интерфейс показывает
до 12 объектов на странице. Регистрация создаёт аккаунт студента. Для зачисления
достаточно передать преподавателю свой логин; самостоятельно вступить в курс нельзя.

Демокнопки показаны только при `DJANGO_DEBUG=True`. Если демопароль изменён,
используйте обычную форму входа. Вход сохраняется при перезагрузке страницы
в текущей вкладке; кнопка **Выйти** очищает токены из браузера.

## Полный цикл одной командой

Для Docker:

```powershell
docker compose exec web python scripts/demo_api.py
```

Для локального сервера:

```powershell
.\.venv\Scripts\python.exe scripts/demo_api.py
```

Опции `--base-url` и `--password` задают адрес сервера и общий пароль демоаккаунтов,
если они отличаются от стандартных. Скрипт использует стандартную библиотеку Python.

Каждый запуск создаёт отдельный курс `[Demo API] Python ...`, зачисляет `demo_student`
и `demo_peer` и проходит цепочку «черновик → публикация → решение → оценка → прогресс».
Он проверяет HTTP 403/404 для запрещённых действий, 409 при повторной сдаче и правке
проверенной работы, приватность решения от другого студента этого же курса,
а также итог 45 из 50 баллов и 100% сданных заданий.
Токены и пароль в вывод не попадают. Успех завершается кодом 0, ошибка - ненулевым.
Созданный курс сохраняется; следующий запуск создаёт новый.

## Сценарий в Swagger

1. Открыть [Swagger](http://127.0.0.1:8000/api/docs/) и выполнить
   `POST /api/auth/token/` с `username: demo_student` и демопаролем. В **Authorize**
   вставить полученный `access` без префикса `Bearer`.
2. Выполнить `GET /api/courses/`. Из `results` взять ID курса `[Demo] Основы Python`.
   В списке его заданий видны три опубликованных задания; черновика `Итераторы` нет.
   В `/api/courses/{id}/progress/` отображается только собственная строка.
3. Для задания `Подсчёт слов` запросить список решений. Видна только своя работа
   с оценкой 80 и комментарием. Попытка изменить ответ возвращает HTTP 409.
4. Для `Коллекции` отправить решение через `POST .../submissions/`, например
   `{"answer": "def unique(values):\n    return list(dict.fromkeys(values))\n"}`.
   Ответ - HTTP 201. Повторный POST возвращает 409; до проверки ответ можно менять
   через PATCH по ID работы. У `Работа с файлами` отправка отклоняется с ошибкой дедлайна.
5. Получить токен `demo_teacher`, заменить токен в **Authorize**, открыть список
   решений задания `Коллекции` и выставить оценку через POST `.../{submission_id}/grade/`:
   `{"score": 45, "feedback": "Решение верное, добавьте тест пустого списка."}`.
   Преподавателю также доступна сводка всей группы.
6. Снова авторизоваться как `demo_student`: оценка и комментарий доступны,
   изменение проверенного решения возвращает 409. Если остальные данные не менялись,
   прогресс - 2 из 3 заданий, 125 из 175 баллов и 66,67% завершённости.
7. Авторизоваться как `demo_other_teacher` и запросить курс Python по известному ID:
   ответ 404. Для `demo_peer` чужое решение `demo_student` тоже возвращает 404.

В запросах коллекций объекты находятся в `results`; поля `count`, `next`, `previous`
описывают пагинацию. Примеры фильтров и параметры сортировки приведены в [API](api.md).
