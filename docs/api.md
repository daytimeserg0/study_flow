# API StudyFlow

[README](../README.md) · [Демонстрация](demo.md)

Интерактивная схема: [Swagger](http://127.0.0.1:8000/api/docs/).

## Пользователи и авторизация

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| POST | `/api/auth/register/` | Регистрация студента |
| POST | `/api/auth/token/` | Вход по username и password; возвращает access и refresh |
| POST | `/api/auth/token/refresh/` | Новый access по действующему refresh |
| GET | `/api/users/me/` | Профиль пользователя, определённого по access-токену |

Пример тела запроса регистрации:

```json
{
  "username": "student01",
  "email": "student01@example.com",
  "password": "StudyFlow-example-73!",
  "first_name": "Иван",
  "last_name": "Петров"
}
```

`username`, `email` и `password` обязательны. Пароль проверяется валидаторами Django
и сохраняется в виде хеша. Ответ содержит профиль и не содержит пароль.
Неизвестные поля, включая `role`, `is_staff` и `is_superuser`, отклоняются с HTTP 400.

Для доступа к профилю используется заголовок `Authorization: Bearer <access>`.
В Swagger токен можно вставить в окно **Authorize**. Refresh-запрос принимает
`{"refresh": "<refresh>"}` и не продлевает срок жизни исходного refresh-токена.
Неверные, просроченные токены и учётные записи с отключённым `is_active` не дают
доступа к API. Редактирование профиля через API пока не поддерживается.

Новый пользователь получает роль `student`. Суперпользователь назначает роль
`teacher` в Django Admin. Роль преподавателя сама по себе не даёт доступа к админке;
административные права определяются отдельными флагами Django.

## Курсы и зачисление

Все запросы требуют access-токен. Преподаватель видит и редактирует только свои
курсы, студент видит только те, на которые зачислен. Запрос чужого курса возвращает
HTTP 404. Административные флаги не расширяют доступ к API: для преподавания
суперпользователю тоже нужна роль `teacher`.

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| GET | `/api/courses/` | Доступные пользователю курсы |
| POST | `/api/courses/` | Создание курса преподавателем |
| GET | `/api/courses/{id}/` | Информация о доступном курсе |
| PUT, PATCH | `/api/courses/{id}/` | Редактирование своего курса |
| GET | `/api/courses/{id}/students/` | Список зачислений, только для владельца курса |
| POST | `/api/courses/{id}/students/` | Зачисление студента владельцем курса |
| GET | `/api/courses/{id}/progress/` | Прогресс студента или группы курса |

Пример создания курса:

```json
{
  "title": "Основы Python",
  "description": "Функции, коллекции и основы работы с файлами"
}
```

Название обязательно, до 200 символов; описание необязательно. Преподаватель
определяется по токену. Передавать владельца, идентификатор и даты в теле запроса
нельзя - такие запросы возвращают HTTP 400. В ответе есть `id`, `title`,
`description`, `teacher`, `created_at` и `updated_at`.

Для зачисления студент сначала регистрируется, затем владелец курса отправляет
`{"username": "student01"}` на `/api/courses/{id}/students/`. Успешный ответ -
HTTP 201 с полями `id`, `course`, `student`, `created_at`. Повторный запрос
возвращает HTTP 409; уникальность пары курс-студент также защищена ограничением БД.
Несуществующий, отключённый пользователь или преподаватель не может быть зачислен.

Вложенные объекты `teacher` и `student` содержат только `id`, `username`,
`first_name`, `last_name`. Студент не получает список однокурсников и не может
редактировать курс или зачислять пользователей. Списки возвращаются постранично.
Удаление курсов и отчисление через API пока не поддерживаются.

## Задания

Задания принадлежат курсу. Преподаватель управляет заданиями своих курсов,
а зачисленный студент видит только опубликованные задания. Черновик скрыт
от студентов, в том числе при обращении по известному идентификатору.

Базовый адрес: `/api/courses/{course_id}/assignments/`.

| Метод | Адрес относительно базового | Назначение |
| --- | --- | --- |
| GET | - | Список доступных заданий курса |
| POST | - | Создание черновика |
| GET | `{id}/` | Условие и параметры задания |
| PUT, PATCH | `{id}/` | Редактирование задания владельцем курса |
| DELETE | `{id}/` | Удаление черновика |
| POST | `{id}/publish/` | Публикация задания |

Пример тела запроса создания:

```json
{
  "title": "Подсчёт слов",
  "description": "Напишите функцию, возвращающую частоту каждого слова в строке.",
  "due_at": null,
  "max_score": 100
}
```

`title` и `description` обязательны и не могут быть пустыми. Название ограничено
200 символами. `max_score` - целое число от 1 до 1000, по умолчанию 100.
`due_at` необязателен: `null` означает отсутствие срока. Дата передаётся в ISO 8601
с часовым поясом, например `2027-09-15T18:00:00+03:00`, и должна быть в будущем.
Ответ дополнительно содержит `id`, `course`, `status`, `published_at`, `created_at`
и `updated_at`; эти поля устанавливает сервер, передавать их в запросе нельзя.

Новое задание имеет статус `draft`. POST на `{id}/publish/` без тела запроса
переводит его в `published` и фиксирует время публикации. Черновик с истёкшим
сроком не публикуется, пока преподаватель не изменит или не уберёт дедлайн.
Повторный запрос публикации возвращает HTTP 200 и сохраняет исходное время
публикации. Вернуть опубликованное задание в черновик нельзя.

Условие, максимальный балл и срок можно редактировать после публикации.
Максимальный балл нельзя снизить ниже любой из уже выставленных оценок.
Истёкший срок не скрывает задание от студентов и не мешает править условие;
проверка даты применяется только при её передаче в запросе и при первой публикации.
Удаление черновика возвращает HTTP 204, удаление опубликованного задания - HTTP 409.
При подстановке в URL другого курса задание остаётся недоступным (HTTP 404).
Списки возвращаются постранично.

## Сдача решений

Зачисленный студент может отправить решение опубликованного задания текстом,
ссылкой или обоими способами. На каждое задание у студента одна работа, которую
можно исправлять до проверки и срока сдачи. Преподаватель видит все работы своего задания,
студент - только свою. Доступ к чужой работе и подмена курса или задания в URL
возвращают HTTP 404. Административные флаги не расширяют эти права.

Базовый адрес: `/api/courses/{course_id}/assignments/{assignment_id}/submissions/`.

| Метод | Адрес относительно базового | Назначение |
| --- | --- | --- |
| POST | - | Отправка решения студентом |
| GET | - | Доступные работы задания |
| GET | `{id}/` | Просмотр решения |
| PUT, PATCH | `{id}/` | Исправление своего решения до проверки и дедлайна |

Пример тела запроса:

```json
{
  "answer": "Решение и тесты находятся в репозитории, функция count_words в main.py.",
  "solution_url": "https://github.com/student/python-homework"
}
```

Нужно заполнить хотя бы одно поле: `answer` (до 20 000 символов) или `solution_url`
(до 500 символов, HTTP/HTTPS). Отступы и переносы строк в ответе сохраняются.
Пустое решение, текст только из пробелов или попытка стереть оба поля отклоняются
с HTTP 400. Ссылка сохраняется без скачивания содержимого; код решения не запускается.
Загрузка файлов пока не поддерживается.

Успешная отправка возвращает HTTP 201. Повторный POST возвращает HTTP 409,
для исправления используется PUT или PATCH по идентификатору существующей работы.
Оба метода сохраняют неуказанные необязательные поля. Работа содержит `id`,
`assignment`, `student`, `answer`, `solution_url`, `status`, `grade`, `submitted_at`, `updated_at`.
Студент и задание определяются по токену и URL; передавать их, даты и неизвестные
поля в теле запроса нельзя. `submitted_at` хранит время первой отправки,
`updated_at` - последнего изменения. История предыдущих версий пока не сохраняется.

Если `due_at` наступил, отправка нового решения и исправление существующего
возвращают HTTP 400 с ошибкой `due_at`. Читать сданные работы по-прежнему можно.
При `due_at: null` ограничений по времени нет. Преподаватель может продлить срок
или убрать его, после чего отправка и исправления снова доступны.
Параллельные запросы отправки и изменения срока обрабатываются с блокировкой
строки задания; уникальность пары задание-студент дополнительно защищена в БД.

Преподаватель не может отправлять или изменять решения за студентов. Удаление
работ через API не поддерживается; в Django Admin работы доступны только для
просмотра. Список для студента содержит ноль или одну работу, для преподавателя -
все работы задания. Результаты возвращаются постранично.

## Проверка работ и оценки

Владелец курса выставляет оценку запросом POST на
`/api/courses/{course_id}/assignments/{assignment_id}/submissions/{id}/grade/`.

```json
{
  "score": 85,
  "feedback": "Решение верное. Добавьте обработку пустой строки."
}
```

`score` обязателен: целое число от 0 до `max_score` задания. `feedback` необязателен,
до 5000 символов. Преподаватель и время проверки определяются сервером.
Оценивать работу можно до и после дедлайна. Ответ HTTP 200 содержит решение
с `status: "graded"` и вложенной оценкой `grade`: `id`, `score`, `feedback`,
`graded_by`, `graded_at`. Объект `graded_by` содержит только идентификатор,
username, имя и фамилию. У непроверенной работы `status: "submitted"`, `grade: null`.

Студент получает свою оценку и комментарий в обычных запросах списка и просмотра
решений. Оценки других студентов ему недоступны. После проверки изменение решения
через PUT или PATCH возвращает HTTP 409, даже если дедлайн ещё не наступил.
Оценивание не меняет текст, ссылку и даты отправки или исправления работы.

Повторный POST на `grade/` исправляет существующую оценку и обновляет время проверки;
второй записи не создаётся. Если не передать `feedback`, предыдущий комментарий
очищается. История оценок и возврат работы на доработку пока не поддерживаются.
Преподаватель проверяет только работы своих курсов; флаги администратора
не дают дополнительных прав в API. Преподаватель сохраняет доступ к сданной работе,
даже если студент позже отчислен с курса.

Оценивание, исправление решения и изменение максимального балла используют общий
порядок блокировок в БД. Одновременные запросы не позволяют изменить уже проверенный
ответ или сохранить оценку выше актуального максимума. В Django Admin оценки
доступны только для просмотра; максимальный балл существующего задания изменяется
через API, где проверяется совместимость с выставленными оценками.

## Списки, поиск и фильтры

Списки курсов, студентов, заданий, решений и прогресса используют единый формат
ответа. Объекты находятся в `results`, общее число доступных результатов - в `count`.
`next` и `previous` содержат ссылки на соседние страницы или `null`:

```json
{
  "count": 0,
  "next": null,
  "previous": null,
  "results": []
}
```

По умолчанию страница содержит до 20 объектов. Параметры `page` и `page_size`
управляют номером и размером страницы; `page_size` ограничен 100. Номер отсутствующей
или некорректной страницы возвращает HTTP 404. Сортировка стабильна: при совпадении
основного поля используется идентификатор. Объекты не повторяются между страницами
при неизменном наборе данных.

| Список | Параметры |
| --- | --- |
| `/api/courses/` | `search` по названию и описанию; `ordering=title` или `created_at` |
| `/api/courses/{id}/assignments/` | `search` по названию и условию; `status=draft` или `published`; `due_after`, `due_before`, `overdue`; `ordering=title`, `created_at`, `due_at`, `max_score` |
| `/api/courses/{course_id}/assignments/{assignment_id}/submissions/` | `search` по username, имени и фамилии автора; `student=<username>`; `status=submitted` или `graded`; `ordering=submitted_at` или `updated_at` |

Для сортировки по убыванию перед полем ставится `-`, например `ordering=-due_at`.
Можно указать несколько разрешённых полей через запятую. По умолчанию первыми идут
новые курсы, задания и решения. Неизвестные поля сортировки игнорируются.

Даты `due_after` и `due_before` передаются в ISO 8601, обе границы включены;
задания без дедлайна в такой диапазон не попадают. `overdue=true` выбирает
опубликованные задания с наступившим дедлайном, независимо от наличия решения.
`overdue=false` выбирает остальные задания, включая задания без срока и доступные
преподавателю черновики. Некорректные статусы, даты, значения `overdue` и обратный
диапазон дат возвращают HTTP 400.

Примеры запросов:

```text
/api/courses/?search=Python&ordering=title&page_size=10
/api/courses/1/assignments/?status=published&overdue=true
/api/courses/1/assignments/2/submissions/?status=submitted&student=student01
```

Поиск и фильтры работают только в запросах списков курсов, заданий и решений.
Они не влияют на просмотр отдельного объекта, запись, публикацию, оценивание,
списки зачислений и прогресса. Сначала применяется ограничение доступа:
фильтры не открывают чужие курсы, черновики или работы однокурсников. Например,
запрос студента с `status=draft` возвращает пустой список заданий.

## Прогресс по курсу

GET `/api/courses/{id}/progress/` возвращает постраничный список. Студент видит
свою строку, преподаватель - строки всех текущих участников своего курса.
Флаги администратора не расширяют доступ. После отчисления строка исчезает из
сводки, но сданные работы и оценки сохраняются.

| Поле строки | Значение |
| --- | --- |
| `student` | Идентификатор, username, имя и фамилия студента |
| `assignments_count` | Число опубликованных заданий курса |
| `submitted_count` | Число сданных работ, включая проверенные |
| `graded_count` | Число проверенных работ; нулевая оценка тоже считается |
| `overdue_count` | Число заданий с наступившим дедлайном, по которым нет решения |
| `earned_score` | Сумма выставленных баллов |
| `max_score` | Сумма максимальных баллов всех опубликованных заданий |
| `completion_percent` | Доля сданных заданий в процентах, с округлением до сотых |

Например, две сданные работы из трёх дают `completion_percent: 66.67`.
Если опубликованных заданий нет, все показатели равны нулю. Черновики и данные
других курсов не участвуют в расчётах. Уже сданная работа не считается просроченной
в сводке, даже если срок задания прошёл. Показатель завершённости не является
процентом набранных баллов.

Показатели рассчитываются агрегатами PostgreSQL. Связанные авторы и оценки
загружаются вместе со списком решений, без отдельного запроса на каждую строку.
Добавлены составные индексы для отбора заданий по курсу, статусу и дедлайну
и для сортировки решений задания по времени отправки.
